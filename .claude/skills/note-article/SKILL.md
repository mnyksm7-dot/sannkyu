# note.com 記事作成自動化

note.com に貼り付けてそのまま使える記事の原稿を作成する。**実際の投稿・下書き保存は行わない**(note.com に公開APIがなく、自動ログインもしない方針のため)。ここで作るのはあくまで原稿とサムネイルのソース。

## 手順

1. **テーマを確認する。** ユーザーの発言からテーマ・キーワード・想定読者・トーン(カジュアル/ビジネスなど)を読み取る。曖昧な場合は簡潔に確認してから書き始める。
2. **出力先を決める。** `output/<YYYYMMDD>-<slug>/article.md` に保存する。`slug` はテーマから短い英数字スラッグを作る(例: テーマ「Claude Codeの使い方紹介」→ `claude-code-usage`)。日付は実行日。
3. **記事を書く。** `article.md` に以下の構成で書く:
   - `# タイトル` — 読者の興味を引く具体的なタイトル
   - リード文(2〜3文) — 記事の要点とこの記事を読むメリット
   - `##` 見出しで区切った本文(3〜6セクション程度)
   - まとめ・締めの一言(CTAがあれば添える)
   - 記事末尾に `## タグ候補` として note.com 用のハッシュタグ候補を5〜10個列挙する
   - 分量の目安は日本語本文でおよそ4000文字前後(ユーザーが別の分量を指定した場合はそちらに従う)。セクション数を3〜6個に抑えたまま無理に埋めず、具体的なエピソードを1〜2個追加する形で文字数を伸ばす
   - 文字数を数えるときは `wc -m` ではなく `python3 -c "print(len(open('<path>', encoding='utf-8').read()))"` のように多バイト文字を正しく数えられる方法を使う(環境によっては `wc -m` がPOSIXロケールで文字化けたカウントを返すことがある)
4. **「人が書いてるふう」の文体にする。** ユーザーから指定がなくても、これは常に意識する:
   - 一般論の羅列ではなく、一人称の実体験・具体的なエピソードとして書く(数字・期間・失敗談を交える)
   - 文の長さやリズムに強弱をつける。整いすぎた箇条書きの多用は避け、地の文で語る部分を増やす
   - 「〜だと思います」「正直〜でした」のような、書き手の迷いや本音がにじむ言い回しを適度に入れる
   - テンプレ的なAI表現(「いかがでしたか」「〜な時代です」「まとめると」を毎回使う、絵文字の多用など)は避ける
   - note.com で売れているジャンル(AI活用・副業・転職/キャリア・投資・SNS運用・恋愛/婚活・子育てなど)を書くときは特に、一般論ではなく「自分がやってみてどうだったか」の視点を核にする
5. **完了したら伝える。**
   - `article.md` のパスを伝える
   - サムネイルも欲しいと言われたら、または未生成なら `note-thumbnail` スキルの利用を提案する
   - note.com への実際の公開・下書き保存はユーザー自身が手動で行う必要があることを明記する
