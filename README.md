# sannkyu

note.com の記事作成とサムネイル作成を自動化するプロジェクトです。Claude Codeのチャットから「note用の記事を書いて」のように頼むだけで、note.comにそのままコピペできる原稿と見出し画像を用意します。

## 何が自動で、何が手動か

| 工程 | 状態 | 補足 |
|---|---|---|
| 記事の執筆 | ✅ 完全自動・無料 | Claudeが直接書くのでAPI不要 |
| サムネ画像プロンプトの作成 | ✅ 完全自動・無料 | 記事のテーマから自動生成 |
| サムネ画像の生成 | 🟡 手動(無料) / ✅ 自動(有料) | 下記「サムネ画像の作り方」参照 |
| サムネ画像のリサイズ(1280x670) | ✅ 完全自動・無料 | スクリプトが処理 |
| note.comへの投稿(下書き保存・公開) | ❌ 常に手動 | note.comに公開APIがなく、自動ログインもしない方針のため |

**つまり、コピペのみで済む状態にするまでの作業は「記事執筆」「画像プロンプト作成」「画像リサイズ」まで全て自動です。** 有料になり得るのはサムネ画像の生成方法を選ぶ1箇所だけで、そこも無料で完結できます。

## サムネ画像の作り方(2パターン)

### 無料パターン(デフォルト・おすすめ)

外部AI画像生成APIはこの環境のネットワークポリシー上呼び出せず(OpenAI/Stability/HuggingFace/Pollinationsいずれも403)、Gemini APIも無料枠は画像生成のクォータが0のため、**画像の生成自体は人がブラウザで行います。**

1. `output/<日付>-<slug>/image-prompt.txt` に用意された英語プロンプトをコピー
2. ChatGPT・Gemini・Bing Image Creatorなど無料の画像生成ツールに貼り付けて画像を作る
3. できた画像をダウンロードして渡す(1枚なら `--input`、複数枚まとめてなら `batch-thumbnails.ts`)
4. こちらでnote.com推奨サイズ(1280x670)にリサイズ・クロップ

ここから先(記事執筆・プロンプト作成・リサイズ)は完全に無料・自動です。

### 有料パターン(GEMINI_API_KEYを課金した場合のみ)

Google AI StudioでGEMINI_API_KEYのプロジェクトに課金を有効化すると、画像生成そのものも自動化できます。1枚あたり数円程度の実費がかかります。

```
GEMINI_API_KEY=xxxx npx tsx scripts/generate-thumbnail.ts --prompt "<英語プロンプト>" --out output/<slug>/thumbnail.png
```

未課金のキーだとここは `RESOURCE_EXHAUSTED` エラーになります(無料枠のクォータが0のため)。

## 1本の記事をコピペのみの状態にするまで

1. チャットで「note用の記事を書いて、テーマは○○」と頼む → `output/<日付>-<slug>/article.md` ができる
2. 「サムネを作って」と頼む → `image-prompt.txt` ができる
3. プロンプトを無料ツールに貼って画像を生成、ダウンロードして渡す → `thumbnail.png` ができる(1280x670)
4. note.comで新規記事を作成し、`article.md` のタイトル・本文をコピペ、`thumbnail.png` を見出し画像にアップロードして下書き保存

4だけが人の手作業です。

## 複数記事をまとめて処理したいとき

10記事など数が多いときは、往復の手間を減らすためにまとめて処理できます。

1. `output/<日付>-thumbnail-prompts.md` のような一覧ファイルに全記事分のプロンプトとファイル名指定(`<slug>.png`)をまとめる
2. 各プロンプトを画像生成ツールに順に貼り付け、指定のファイル名で1つのフォルダにまとめてダウンロード
3. まとめて渡してもらえれば以下を実行:
   ```
   npx tsx scripts/batch-thumbnails.ts --input-dir <画像フォルダ>
   ```
   ファイル名(拡張子抜き)が `output/<日付>-<slug>/` フォルダのスラッグと一致するものだけを自動でリサイズし、それぞれの `thumbnail.png` として保存する。一致しなかったファイルはスキップ理由付きで報告される。

## ディレクトリ構成

```
sannkyu/
├── .claude/skills/
│   ├── note-article/SKILL.md      # 記事作成スキル
│   └── note-thumbnail/SKILL.md    # サムネ作成スキル
├── scripts/
│   ├── generate-thumbnail.ts      # 1枚をリサイズ or Gemini APIで生成
│   └── batch-thumbnails.ts        # フォルダ内の複数枚を一括処理
├── output/
│   └── <日付>-<slug>/
│       ├── article.md             # note.comにコピペする記事本文
│       ├── image-prompt.txt       # サムネ用の画像生成プロンプト
│       └── thumbnail.png          # 出来上がったサムネ画像(1280x670)
└── .env.example                   # GEMINI_API_KEY=(有料パターンを使う場合のみ)
```

## セットアップ

```
npm install
```

これだけで無料パターンはすぐに使えます。有料パターンを使う場合のみ `GEMINI_API_KEY` を環境変数として設定してください(`.env.example` 参照)。

## 毎日まとめて記事を作りたい場合

「毎日10記事」のような定期実行には向き不向きがあります。

- **このセッション内**であれば、CronCreateで定期実行を組めますが、セッションはこのクラウド環境の生存期間に紐づくため、コンテナが片付けられると止まります(最大7日間)。
- **本当に無期限で毎日自動実行したい**場合は、GitHub Actionsなど、このセッションの外側で動くスケジューラと、記事生成を呼び出すLLM API連携を別途組む必要があります。これは現状未実装です。
- 現実的な運用としては、毎日このチャットで「note用の記事を10本書いて」と頼む(テーマは固定ジャンルをローテーションするか、都度指定する)のが、追加の仕組みなしに今すぐできる方法です。
